# Output Format

Reference this file whenever writing up scout results (`SKILL.md` Section 4, step 6).

---

## Per-Opportunity Fields

Every opportunity in the daily list must include all of these fields, in this order. Write "not yet identified" rather than dropping a field.

- **Company**
- **Industry**
- **Stage** (funding stage / profitability status)
- **Employee count**
- **Decision-maker** (name + title)
- **LinkedIn profile** (person, and/or company page)
- **Website**
- **Recent buying trigger** (what happened, and when — must be dated)
- **Why they are a strong fit** (2–3 sentences tying ICP + signal together)
- **Business challenges Meiseki could solve** (specific, using the problem-mapping table in `icp-and-signals.md` — not generic "they could use help with growth")
- **Estimated urgency (1–10)**
- **Estimated budget fit (1–10)**
- **Introduction path** (warm intro route if one exists — mutual connection, portfolio relationship, shared community — or "cold outreach" if none)
- **Recommended first outreach angle** (one sentence: the specific hook, not a generic pitch)
- **Recommended conversation starter** (an actual opening line or question, ready to send/say)
- **Bucket** (Direct Client / Referral Partner / Trigger Opportunity)

---

## Daily Report Structure

1. **Header**: date, and a one-line summary of the day's strongest theme if one emerges (e.g. "Heavy signal day for Series A fintechs entering EU market").
2. **Ranked list of up to 10 opportunities**, highest → lowest likelihood of becoming a paying client (referral partners ranked by likelihood of a warm intro instead).
3. **Bucket tally** at the end: how many direct client / referral partner / trigger opportunities made the list, vs. the 50/30/20 target — flag if a bucket came up short and why (e.g. "referral partner search light today — recruiters are quiet in August").
4. **Watch list (optional, separate section)**: strong ICP fits with no qualifying signal yet — not counted in the 10, but worth re-checking on a future run.
5. **Logging note**: which of today's opportunities (if any) the user wants pushed into Clay (for further enrichment) or Apollo (as Accounts/Contacts/Tasks) — don't write to either system without confirmation unless told this is now standing practice.

---

## Field Notes for Logging to Apollo (once confirmed)

When the user confirms an opportunity should be logged:

- **Account** = the Company, with industry/employee count/website as account fields
- **Contact** = the Decision-maker, linked to the Account
- **Label** = the Bucket (`direct-client`, `referral-partner`, `trigger-opportunity`) plus an urgency tier if useful (e.g. `urgent`)
- **Task** = the Recommended first outreach angle, due-dated for follow-up
- Do not create an Apollo Sequence until the user has actually decided to run outreach — logging the Account/Contact/Task is enough at research stage.
